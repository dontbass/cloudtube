# План переработки кода CloudTube

Цель: постепенно заменить наследие Clipious своим кодом — быстрее, проще, без ошибок,
по современным правилам Flutter/Dart. Каждый этап — отдельная сборка, которую можно
проверить и при проблеме откатить. Интерфейс не ломаем: сначала фундамент, потом экраны.

Состояние на 17.11.2026 (v1.1.50): ~41 тыс. строк рукописного кода, из них ~8 тыс. своих,
~33 тыс. — Clipious (≈20 тыс. ни разу не менялись). Установщик arm64 — 16,8 МБ.

## Принципы

- **Один способ на задачу.** Сейчас дублируются: два HTTP-клиента (`http` и `dio`),
  две базы (файловая `FileDB` и `sembast`+`sqflite`), три плеера (`river_player` на
  Android, `media_kit` на Windows, `just_audio` для звука), две библиотеки фона
  (`audio_service` и `awesome_notifications`+`workmanager`).
- **Тонкие экраны, логика отдельно.** Экран только рисует; загрузка, кэш и правила —
  в слое данных (`repository`) с тестами.
- **Строгий анализатор.** `strict-casts`, `strict-inference`, `strict-raw-types`, запрет
  `dynamic` без причины, `prefer_const`, `unawaited_futures`. Сборка падает на предупреждениях.
- **Иммутабельные модели** (`freezed`), без изменяемых полей у видео/каналов.
- **Измеряем, а не угадываем:** время запуска, кадры при прокрутке, память, размер APK —
  до и после каждого этапа.

## Этап 0. Основа (1 сборка, без видимых изменений)

- Строгие правила анализатора; исправить всё, что они найдут (это и есть скрытые ошибки).
- Убрать `any` из версий зависимостей (`http`, `intl`, `path`, `awesome_notifications`…) —
  сборки должны быть воспроизводимыми.
- Удалить отладочные сценарии сборки (`probe.yml`, `direct_probe_test.dart`) и разовые
  скрипты сервера (`collect-*.sh`) — по согласованию.
- Тесты: восстановить существующие, добавить на адаптер «без сервера» (разбор ответов
  YouTube на сохранённых образцах) — самое хрупкое место.
- Замеры: время до первого кадра, до первой плитки, FPS при прокрутке ленты на ТВ.

## Этап 1. Слой данных

- **Один HTTP-клиент** (`dio`): общие таймауты, повторы, отмена запросов при уходе с экрана,
  кэш ответов. Сейчас загрузки идут через `dio`, остальное — через `http`.
- **Репозитории** вместо «толстого» `service.dart` (≈1000 строк): `VideoRepository`,
  `ChannelRepository`, `FeedRepository`, `AccountRepository`. Источник (свой сервер /
  YouTube напрямую) выбирается внутри, экраны о нём не знают.
- **Адаптер «без сервера»** (`direct.dart`, ~1000 строк): разделить на разбор ответов YouTube
  и эмуляцию API Invidious; разбор вынести в отдельные функции с тестами.
- **Кэш в памяти с ограничением** (LRU) вместо разрозненных `Map` по файлам.
- **Тяжёлый разбор JSON — в изолятах** (`compute`), чтобы не подтормаживал интерфейс.

## Этап 2. Хранение

- **Одна база.** Оставить `sembast` (или перейти на `drift`, если понадобится поиск по
  истории); `FileDB` и вторую реализацию интерфейса — удалить.
- Перенос данных при обновлении: настройки, история просмотра, подписки, загрузки —
  с проверкой на копии базы.
- Настройки — типизированный объект вместо строк-ключей (`'ct-tv-quality'` и т.п.).

## Этап 3. Плеер

- Единое «ядро плеера» (очередь, следующий ролик, качество, восстановление при сбоях,
  SponsorBlock, позиция) — общее для телефона, ТВ и Windows. Сейчас логика размазана по
  `player.dart`, `video_player.dart`, `tv_player_controls.dart`.
- Звук без видео — через тот же плеер, убрать `just_audio`, если получится без потерь.
- Свой DASH/HLS-выбор качества оформить отдельным модулем с тестами.

## Этап 4. Экраны (по одному за сборку)

Порядок — по заметности для пользователя:

1. Страница канала (телефон и ТВ).
2. Страница плейлиста.
3. Загрузки.
4. Управление подписками.
5. Поиск и подсказки.
6. Страница ролика и мини-плеер на телефоне.
7. Вложенные экраны настроек — уже в стиле CloudTube, переписать на типизированные настройки.

Для каждого: общий набор компонентов (`CtCard`, плитка ролика, заголовки, пустые состояния,
ошибки с кнопкой «Повторить»), ленивые списки, `const`-виджеты, `RepaintBoundary` у плиток.

## Этап 5. ТВ

- Единая модель фокуса и прокрутки вместо точечных правок (`tv_nav.dart`, `tv_home.dart`).
- Предзагрузка следующей страницы ленты и картинок по направлению движения.
- Замер и цель: стабильные 60 кадров при удержании стрелки.

## Этап 6. Фон и уведомления

- Одна библиотека уведомлений; фоновая проверка через `workmanager` с общим слоем данных.
- Колокольчик канала и подписки — в одном месте.

## Этап 7. Завершение

- Удалить оставшиеся каталоги Clipious и неиспользуемые зависимости; сменить пакет
  `com.github.lamarios.clipious` в коде (имя установленного приложения не меняется).
- Итоговые замеры и сравнение с началом.

## Как проверяем каждый этап

- Сборка без предупреждений анализатора, тесты зелёные.
- Короткий список проверок для пользователя (что открыть, что нажать).
- Сравнение замеров с предыдущей версией; если хуже — откат этапа.
